# Button 125 (Mode underline / aw-obys-underline) — remove stage background + theme-aware ink

**Date:** 2026-09-02
**Request:** "for the 125th button remove the bg and make the buttons white for dark theme and black for light theme dont change anything else"

## Scope

Tray #125 = `aw-obys-underline` ("Mode underline", Awwwards category) — obys.agency's work-mode
toggles: Vertical / Horizontal / Grid text buttons with a 1.34px underline that draws origin-left
on activate and collapses origin-right on deactivate, plus a small ↻ cycle control.

Only two behaviors changed; nothing else (markup, JS, easing, timings, underline mechanics untouched):

1. **Stage background removed** — `.obys-stage` no longer paints `background: #f2f0eb` (+ its
   border-radius). The button now sits directly on the gallery's `.slot-preview` well
   (`var(--well)`: `#e8eaee` light / `#121315` dark), which is itself theme-aware.
2. **Theme-aware ink** — one custom property drives every ink color:
   - `.obys-underline-root { --obys-ink: #0e0e0e; }` (light: black)
   - `:root[data-theme="dark"] .obys-underline-root, [data-theme="dark"] .obys-underline-root { --obys-ink: #ffffff; }`
   - active label / underline / hover-full: `var(--obys-ink, #0e0e0e)`
   - inactive label: `color-mix(in srgb, var(--obys-ink, #0e0e0e) 40%, transparent)` (was `rgba(14,14,14,.4)`)
   - hover label: `… 75%, transparent`; cycle mark: `… 50%, transparent`; focus outlines: the var.

The old `--aw-mode-ink: 1` marker stays (integration test + `plans/awwwards-10-catalog.json` pin it).

No `prefers-color-scheme` fallback: standalone snippet pages have no `data-theme` attribute, so a
system-dark fallback would render white ink on the snippet's white page (invisible). The house
`explore-now` pattern needed that fallback only because its dark-mode override softened a color
that stays visible on white.
